### P0-7 为什么还是空

```kotlin
// :205 列表显示名是对的
val displayName = job.name.ifBlank { "未命名（${job.total}章）" }
// :207 但点击时传的是空串
) { openBook(job.bookId, job.name.ifBlank { "" }, job.author) }
```

`job.name` 为空 → 传 `""` → `openBook` 内 `job.name.ifBlank { name }` 仍得 `""`。目录页标题空白、导出首部仍是「未命名」，同源。

改成 `openBook(job.bookId, job.name, job.author)` 并在 `openBook` 里保留「未命名」兜底即可。

## 三、新问题

### P0-9 · 三个新入口画不出来，改名列删除名全部不可达

- 现象：首页条目右侧没有「⋮」。点条目右半边空白，直接进入目录页（`r3-08`）。
- 定位：`Widgets.kt:120-153`。`trailing` 的构造写在 `else`（单行）分支里；`twoLine` 分支只加 title 与 subtitle，**从未添加 trailing**。首页调用 `listItem(..., twoLine = true, trailing = "⋮", onTrailingClick = ...)`，参数被静默丢弃。
- 影响：本轮新增的 `showJobMenu` / `renameJob` / `confirmDeleteJob` 三个函数用户无法到达；第 2 轮 P0-6 仍未解决。
- 修法：把 trailing 的构造提到分支外，twoLine 分支里用横向容器：

```kotlin
val trailingView = trailing?.let { t ->
    Md3.text(ctx, t, Md3.FS_SM, trailingColor).apply {
        setPadding(Md3.dp(ctx, 6), 0, 0, 0)
        if (onTrailingClick != null) { isClickable = true; setOnClickListener { onTrailingClick() } }
    }
}
if (twoLine) {
    val row = LinearLayout(ctx).apply { orientation = LinearLayout.HORIZONTAL }
    row.addView(titleView, LinearLayout.LayoutParams(0, WRAP_CONTENT, 1f))
    trailingView?.let { row.addView(it) }
    item.addView(row, LinearLayout.LayoutParams(MATCH_PARENT, WRAP_CONTENT))
    // subtitle 照旧
}
```

### P0-10 · 从首页点开已下载的书，点章节必崩

- 现象：首页进 `未命名（143章）` → 目录页 → 点第 1 章 → 应用进程消失，虚拟屏变黑。
- 日志：`FATAL EXCEPTION: main` / `android.os.NetworkOnMainThreadException`，栈顶落到 `MainActivity.preview(MainActivity.kt:959)` → `getSource` → `DeviceRegister.get` → `Http.fetchRaw`。两次独立复现：08:33:29（pid 2453）、08:35:52（pid 5998），第二本换成 `未命名（1645章）` 同样崩。
- 定位：

```kotlin
// :954 preview()，主线程
val src = (screen as? Screen.Toc)?.src
    ?: (screen as? Screen.Reader)?.src
    ?: tocSrc ?: source          // ← 这里凭空把懒加载的 source 求值，触发联网
```

`source` 是 `by lazy { DeviceRegister.get(...) }`（`:73-75`），首次求值要联网注册；从首页进来的目录页 `src` 与 `tocSrc` 都为空，于是退到 `source`，在 UI 线程发起网络请求，StrictMode 直接抛异常，进程退出。后台线程里的 `try/catch` 拦不到——它发生在 `thread { }` 之前。

- 讽刺之处：本地 143 章全在 `chapters.jsonl` 里，`readChapters` 本来能出正文；是先求源把应用弄死的。
- 修法：把取源挪进线程，并且**先读本地，读不到再取源**：

```kotlin
thread {
    try {
        val line = jobsStore().readChapters(info.bookId)[ch.itemId]
        val html = line?.let { TinyJson.path(it, "content") }
            ?: (src ?: source).content(ch.itemId, info.bookId)   // source 只在后台线程碰
        ...
```

## 六、复现要点

```sh
/~vd/vd.sh start 378 496 320
ID=$(cat ~/tmp/vd.id)
/system/bin/su -c "unset LD_LIBRARY_PATH LD_PRELOAD; /system/bin/am start --display $ID -n com.watchdl/.MainActivity"

# 崩溃取证
/system/bin/su -c 'logcat -b crash -d | grep -E "FATAL|NetworkOnMain"'
```

**环境坑（本轮新增）**：
1. 息屏时间 30 秒（`screen_off_timeout=30000`）。必须在两次操作之间注入 `input -d <id> keyevent 224`（每 12 秒一次）把计时顶回去，否则虚拟屏整组断电、输入注入失效。
2. **应用崩溃后虚拟屏会卡死**：`frame.rgba` 的 mtime 停在崩溃那一刻，之后 `vd.sh shot` 一直返回同一张黑图，`dumpsys display` 仍报 `state ON`。必须 `vd.sh stop && vd.sh start` 重建。
3. 杀后台保活循环别写 `pkill -f "keyevent 224"`，会把自己的 `bash -c` 一起杀掉（命令串里含同样字面量）。用 `pkill -f "keyeven[t] 224"`。
