## 五、环境问题：pi 反复被拖死，根因已定位

`vd.sh shot` 每次都开一个 `su` 子壳去 `cp` 帧文件。这个子壳偶尔永久挂住：

- 工具调用不返回 → 用户中断 → 在飞的模型请求被杀 → 整轮静默结束；
- `cp` 没执行时，转换的是上一张旧帧，表现为「画面冻结、md5 相同」，第 5 轮报告里的「虚拟屏冻结」有一部分就是这个假象。

**已改**：`vd.sh shot` 直接读 `/data/local/tmp/frame.rgba`（目录 other 有 x 位，文件 644），全程不再经 `su`。截图耗时从多次 root 调用降到 0.24 秒。

**保活**：
- `termux-wake-lock` 已开；
- `com.termux` 已加入 Doze 白名单（`cmd deviceidle whitelist`），`RUN_IN_BACKGROUND` / `RUN_ANY_IN_BACKGROUND` 均 allow；
- `~/vd/vd-watch.sh` 每 30 秒把 Termux、`node`（pi）、`next-server`（pi-web）的 `oom_score_adj` 压到 -900。

**看门狗**：`~/vd/vd-watch.sh start com.watchdl/.MainActivity`
- 全黑帧 → 立即重建虚拟屏；
- 点击后 12 秒帧 md5 不变 → 重建；
- 重建后自动重新拉起应用，并弹通知。

## 六、复现要点

```sh
~/vd/vd-watch.sh start com.watchdl/.MainActivity     # 看门狗 + 保活
~/vd/vd.sh start 378 496 320
ID=$(cat ~/tmp/vd.id)
/system/bin/su -c "unset LD_LIBRARY_PATH LD_PRELOAD; /system/bin/am start -S -n com.watchdl/.MainActivity --display $ID"
~/vd/vd.sh shot ~/tmp/a.png                          # 0.24 秒，不再走 su
```

注意：`am force-stop` 在本机 ROM 上不存在，重建进程用 `am start -S`。
APK 覆盖安装后运行中的进程仍是旧代码，必须 `-S` 重启才能看到改动。
