## 1.4 两条硬约束（调研得出的，不是猜的）

**① 手表上没有 git 二进制，也没有 Termux。**
所以「git 同步书源」只能实现成：拉仓库的 raw 文件 URL，用 commit sha / ETag / Last-Modified 比对。
不需要 jgit，也不需要真 git 协议。

**② 屏只有 189×248 dp。**
MD3 标准尺寸阶（应用栏 56 + 搜索框 48 + 按钮 40 = 144dp）吃掉 58% 屏高。
所以本项目全部按紧凑档取值（36 / 34 / 42 / 34），`Md3.dp()` 再按屏宽档位放大。
竞品无一采用标准 MD3 尺寸阶。这是品类共性约束，不是本项目独有的缺陷。

### 搬运模式：写成 MainActivity 的扩展函数

这些屏函数要用 Activity 的 `root` / `setScreen` / `crownStep` / `toast` / `bg` 等状态。
写成独立类就得给每个成员加 `a.` 前缀，diff 大几倍。写成扩展函数能直接取。

机械变换只有四种：

1. `private fun foo(...)` → `internal fun MainActivity.foo(...)`（跨文件调用才要 internal）
2. 函数体内 `this@MainActivity` → `this@foo`（在 `.apply {}` 或 lambda 里取 Activity 用）
3. 函数体去掉 4 格缩进（类成员 → 顶层）
4. `screen` 的**读**改成 `curScreen`（见 2.5 坑②）

`MainActivity` 补一行 `import com.watchdl.ui.<组>.*`，调用点一个字不改。
被搬动代码引用到的 Activity 成员改成 `internal`。

## 2.5 两个技术坑（都踩实了）

**① 扩展属性不能有初始化器。**
所以凡是带初始值的 `var` 都搬不走，必须留在 Activity：`readerSize` `readerSpacing` `readerBackground` `readerBody` `readerIndex` `readerOffset` `scrollSave` `rankCache` `rankRefreshed` `rankRefreshing` `hitsWinStart` `tocWinStart` `seenHits`，以及常量 `TOC_WINDOW` `INTRO_LINES` `HITS_WINDOW`。

**② `internal var screen` 会和 `internal fun setScreen` 撞 JVM 名。**
两者都编译成 `setScreen$main`，编译器直接报 `platform declaration clash`。
解法是 `screen` 保持 private，另给一个只读入口：

```kotlin
internal val curScreen: Screen get() = screen
```

搬出去的代码里 `screen as? Screen.X` 一律改成 `curScreen as? Screen.X`。

**③ 有个自检会扫源码文本。**
`test/P0RegressionTest.kt` 里写死 `src.indexOf("private fun extractAssets()")`。把 `extractAssets` 改成 `internal` 之后它就报「找不到 extractAssets」。
已改成只锚函数名 `" fun extractAssets()"`，否则以后每搬一个成员都可能误报。
