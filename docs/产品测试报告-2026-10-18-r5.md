## 三、P1-28 · 阅读设置选完不关闭

- 现象：点「背景：白」后，对话框仍停在屏幕上；背后的阅读页已经变成白底，但被对话框挡住，用户看不见。
- 证据：`r5-10`（点完之后对话框仍在），`r5-11`（手动点「关闭」后才看到白底正文）。
- 定位：`MainActivity.kt:1288-1306`，每个按钮的 `onClick` 里只做 `showReader(...)`，没有 `dialog.dismiss()`；而 `setItems` 版的旧实现是选完自动关的。
- 影响：改字号、行距、背景后都没有反馈；用户会重复点，或认为功能坏了。
- 修法：

```kotlin
val dlg = android.app.AlertDialog.Builder(this).setTitle("阅读设置")
    .setView(ScrollView(this).apply { addView(list) })
    .setNegativeButton("关闭", null)
    .create()
labels.forEachIndexed { i, label ->
    list.addView(Widgets.button(this, label, "text") {
        when (i) { /* ... */ }
        dlg.dismiss()                       // 先关，再重绘
        showReader(info, index, text, src)
    })
}
dlg.show()
```

## 六、复现要点与环境问题

```sh
~/vd/vd.sh start 378 496 320
ID=$(cat ~/tmp/vd.id)
/system/bin/su -c "unset LD_LIBRARY_PATH LD_PRELOAD; /system/bin/am start --display $ID -n com.watchdl/.MainActivity"
# 首页点书 → 目录点第 1 章 → 右上齿轮 → 点「背景：白」→ 点「关闭」
```

**本轮最大障碍：虚拟屏反复冻结。** 三次出现同一症状——`vd.sh shot` 连续返回**字节完全相同**的 PNG，`input` 注入也无效。判据与处置：

- 两个 PNG 的 `md5sum` 相同 = 截帧已停，不要继续点。
- `dumpsys window` 仍能看到 `com.watchdl` 的两个窗口（Activity + Dialog），说明窗口还在。
- 抓主线程栈（`kill -3 <pid>` → `/data/anr/trace_01`）显示 main 停在 `Looper.loopOnce` 的消息队列等待，**不是应用卡死**。
- 处置：`vd.sh stop && vd.sh start` 重建，应用状态会保留（`am start` 后回到原屏）。

触发点集中在打开第二个窗口（`AlertDialog`）之后，第 4 轮打开菜单时也曾出现。真机上是否复现未知，但每次都要重建虚拟屏，测试成本很高。
