- 应用：`com.watchdl`（WatchDownloader 1.0.0-release，2026-10-17 20:23 构建）

- 测试日期：2026-10-17 夜 至 2026-10-18
- 环境：Android 16，虚拟屏 378×496 @320dpi（自建 `~/vd`，displayId 18），root
- 证据截图：`docs/shots-2026-10-18/`
- 结论：**引擎可用，产品不可发。** 能搜、能下、能导出；不能读。

## 一、判定

下载器承诺两件事：把书下到本地，离线能看。第一件做到了，第二件没做。
本轮实测一本 143 章的书全量下载成功，随后点“下一章”失败并被弹回目录。
这是产品主路径断裂，不是边角缺陷。

引擎侧无责：`bash build.sh e2e 三体 2` 六项全绿（84 源 → 1731 命中 → 482 本不同书 → 143 章 → 2 章 14111 字）。

## 三、P0（阻断发布）

### P0-1 已下载的书读不了，翻章必失败

- 现象：下载完成后点「下一章」，2 秒内弹回目录，提示「正文失败：响应缺 y 头（itemId=…）」。
- 证据：`t27-next.png`。该书 143 章全部落盘（`chapters.jsonl` 2.63 MB）。
- 根因两处，同一条路径上：
  1. `preview()`（`MainActivity.kt:918`）**永远联网取正文**，不读 `chapters.jsonl`。
  2. `preview()` 取源用 `(screen as? Screen.Toc)?.src`；从阅读器翻章时当前屏是 `Screen.Reader`，判断为 null，源退回番茄。`FanqieApp.kt:163` 报错，`catch` 里 `showToc(info)` 把用户弹回目录。
- 建议（两处，各一到三行）：
  1. `Screen.Reader` 加字段 `src: BookSource?`，`replay` 与 `showReader` 一并透传；`preview` 取源改为 `(screen as? Screen.Toc)?.src ?: (screen as? Screen.Reader)?.src ?: tocSrc ?: source`。
  2. `preview` 先查本地：`JobStore.readChapters(bookId)[itemId]` 命中即直接渲染，未命中才联网。

### P0-2 作业没有书名，最近下载无法辨认

- 现象：首页两行分别只有「· 已下 143 / 143 章」「· 已下 0 / 0 章」。
- 证据：`t21-home3.png`；`job.json` 中 `"name":""`、`"author":""`。
- 影响：下过三本书以后，列表不可用。目录页标题栏、阅读器标题栏同样为空。
- 定位：写入作业时没有落 `BookInfo.name` / `author`。
- 建议：落盘时写入书名与作者；老作业读不到名字时显示「未命名」，不要显示空标题加前导分隔点。

### P0-3 导出文件名不可归属

- 现象：导出产物为 `_1018_0644.txt`。文件名前半段是空书名。
- 证据：`files/export/_1018_0644.txt`，2.59 MB。
- 影响：导三本书得到三个 `_mmdd_hhmm.txt`，用户无法判断哪本是哪本。TXT 正文里也没有书名与作者头。
- 定位：`File(dir, "${safe}_$stamp.txt")`，`safe` 取自空书名。
- 建议：`safe` 为空时退回 bookId 或「未命名」；TXT 首部加一行书名 + 作者。

### P0-4 空关键词的搜索弹窗没有出口

- 现象：点弹窗外不关，按返回键不关。唯一出路是输入文字再点「搜索」。
- 定位：系统 `AlertDialog`（`MainActivity.kt:716`），未处理取消。
- 建议：加「取消」按钮，并允许点外部与返回键关闭。

### P0-5 搜索命中的书多数打不开目录

- 现象：关键词「1980」，五次尝试、四本书，目录全部失败。只给一句「可能是站点都改了」。
- 影响：搜索给出 285 条结果，用户点进去大概率是死路，且没有自救动作。
- 建议：失败页提供两个动作——「换源重试」「返回搜索」；失败源可在设置里一键禁用。

## 五、对上一份报告的更正

2026-10-17 版报告有两处判断需要撤回，避免修错地方：

1. **「下载会永久卡死」不成立。** 本轮实测在 94/143 处停顿两分多钟（线程栈停在 `Http.fetch(Http.kt:101)` 的 socket 读），随后自行跑完。
   真问题是无速度、无剩余时间、无停滞提示、无总时限——用户看到冻结的数字，无法判断死活。
2. **「导出 TXT 脏」不成立。** 导出会清标签：2.59 MB 产物里只剩 1 个 `</a>`、0 个 HTML 实体。
   脏的是 `chapters.jsonl` 的原始存储（94 章里 9872 个 `</p>`、345 个 `</em>`）。将来加阅读器必须再清一次。

上一份报告的 P0-1（标题露 `<em>`）本轮未复现，判断已修复。

## 七、复现要点

```sh
# 虚拟屏（378×496@320，手表尺寸）
~/vd/vd.sh start 378 496 320
/system/bin/su -c 'am start --display <id> -n com.watchdl/.MainActivity'

# 中文输入：input text 传不了中文，走剪贴板
~/vd/vd.sh clip 三体
~/vd/vd.sh paste          # 等价于往焦点输入框发 KEYCODE_PASTE

# 看界面（OCR，约 200 token）
~/vd/vd.sh shot ~/tmp/x.png && SCALE=2 ./vd.sh shot ...
~/vd/vd-ocr.sh

# 引擎活体自检（不装 APK，1~2 分钟）
cd ~/WatchReader && bash build.sh e2e 三体 2
```

注意：真机锁屏会盖住虚拟屏，且解不开（`locksettings get-disabled=false`）。测试期间勿锁屏。
