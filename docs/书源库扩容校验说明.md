# 书源库扩至 33 条：校验说明

结论：内置书源由 17 条扩到 33 条，新增 16 条全部通过在线实测与独立复测。
`app/assets/sources/legado.json` 现为 33 条、90178 字节、md5 `936983cf439bb831d3661a2818d07c13`。

## 为什么要这么筛

书源失效多是静默的：搜索返回空、目录只有首页、正文是广告页。
只按 URL 能打开判断，会把这类坏源放进库，用户搜索时才空手。
判据必须走真实引擎：搜索命中、完整目录不截断、首中末三章正文合格。

- 每源最多试 3 个关键词，每个关键词最多取 2 本。
- 目录不截断，至少 3 个非公告章节。
- 每章至少 300 汉字、80 个不同汉字，三章正文互不相同，拒错误页。
- 超时与截断记未定，不判永久失效；复测通过才计入。

## 怎么做的

1. 本地候选 1542 条按 `bookSourceUrl` 去重，逐批实测 320 条，得 16 条。
2. 剩余候选按站名去重，避开同站旧域，测 741 条，再得 14 条。
3. Yiove 市场现行规则拉 100 条详情，与本地排重得 42 条，测后新增 0 条。
4. 首轮通过 30 条复测，29 条直接通过；飞卢 `b.faloo.com` 首测报 HTTP 302，独立再测通过。
5. 合并前按主机去重，剔除与内置库同站者，最终新增 16 条不同站点。

复现命令（`$PREFIX` 为 Termux 前缀，探针类在 `build/test.jar`，先跑 `bash build.sh test` 生成）：

```sh
cd ~/WatchDownloader

  --candidates <候选.json> --out <新目录> \
  --classpath "build/test.jar:build/app.jar:libs/rhino-slim.jar:$PREFIX/opt/kotlin/lib/kotlin-stdlib.jar" \
  --workers 3 --first-timeout 22 --total-timeout 100 --no-retry
```
