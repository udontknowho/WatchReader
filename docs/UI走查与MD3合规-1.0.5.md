## 二、布局错误

### P0-1 空状态符号不居中

**现象**：目录失败页的 `⚠` 墨迹横跨 x=43…91，中心 67；屏幕中心 189。偏左 122 px（约 61 dp）。搜索中页的 `🔍` 同样偏左。

**证据**：`r8-11-toc-failed.png`、`r8-03-searching.png`；像素扫描得上述数值。

**根因**：`Widgets.emptyState()` 只给 message 设了 `gravity = Gravity.CENTER`，承载符号的那个 TextView 没设。容器 `box` 的 `gravity=CENTER` 对它无效，因为子 View 宽度撑满、内部文字仍靠左。搜索中页是同一段逻辑的第二份手写拷贝（`MainActivity.kt` 里 `addView(Md3.text(this, "🔍", 30f, …))` 那一行），错法一样。

**建议**：符号 TextView 补 `gravity = Gravity.CENTER`。两处一起改，或把搜索中页改成复用 `emptyState`。

### P0-2 目录失败页两按钮贴在一起

**现象**：填充按钮「换源重试」底边 y=381，文字按钮「返回搜索」首行墨迹 y=386。间距 2.5 dp，眼睛看不到缝。屏幕下方还空着 110 px 没用。

**证据**：`r8-11-toc-failed.png` 放大后可见两行文字直接接在胶囊下沿。

**根因**：`showTocFailed()` 给 `emptyState` 挂了 `lpWeight(1f)`。这个 weight 挂在 ScrollView 内的 `wrap_content` 列上，剩余高度算不出来，布局位置靠碰；两个按钮之间也没有设 margin。

**建议**：去掉 weight，改固定上留白；两按钮之间加 `Md3.GAP`。

### P0-3 阅读器底栏页码掉到第二行

**现象**：「‹ 上一章」「下一章 ›」的墨迹在 y=432…452，页码「1 / 1645」在 y=454…470。三者不在同一基线上，底栏读起来是两行。底栏设计高度 34 dp，实际占用超过 68 px。

**证据**：`r8-07-reader.png`，逐行像素统计。

**根因（推断，未复现）**：底栏是单行 `LinearLayout`，`prev` 与 `next` 各占约 118 px，页码拿剩余宽度。页码 TextView 没设 `setSingleLine()`，宽度不足时折行会撑大行高。但截图里页码只有一行，与折行推断矛盾，修前需复现确认。

**建议**：页码加 `setSingleLine(true)` 与固定 `layout_height`，先修再看是否复现。

### P0-4 对话框沿用系统主题

**现象**：搜索弹窗与阅读设置弹窗的面板底色实测 `#1D211B`（偏绿），应用主底色是 `#141218`（中性偏紫）。输入框光标是系统绿。两个弹窗的圆角、标题字重、按钮排布都跟应用其余部分不同源。

**证据**：`r8-02-search-dialog.png`、`r8-08-reader-settings.png`；像素取样 `(320,160) = (29,33,27)`。

**根因**：两个原因叠加。
1. `app/res/values/styles.xml:9` 的 `AppTheme` 父主题是 `@android:style/Theme.DeviceDefault.NoActionBar`，不是 Material3。
2. `Widgets.styleDialog()` 只改了标题与按钮的文字颜色，没换面板底色，也没设 `colorControlActivated`。

**建议**：换主题父类为 `Theme.Material3.Dark.NoActionBar` 可一次修掉面板色与光标色。若暂时不动主题，至少在 `styleDialog` 里设 `window.setBackgroundDrawable(Md3.bg(surface3, 28))`。

## 三、一致性

### P1-5 选中态两套配色

- 发现页的站点/频道按钮：浅紫填充 `#D0BCFF` + 深字。
- 阅读设置的字号/行距/背景选中：深紫填充 + 浅字。

同一应用两种选中语义。见 `r8-12-discover.png` 与 `r8-08-reader-settings.png`。

### P1-6 图标三套体系

| 体系 | 出现位置 |
|---|---|
| 彩色 emoji | `🔍`（搜索中）、`🔒`（付费章）、`📚`（首页空态） |
| Unicode 文字符号 | `⋮` `⤓` `✓` `✗` `⟳` `⚠` `←` `↓` |
| 细字重箭头 | 顶部返回、发现页刷新 |

`Widgets.searchBar` 的注释已写明「不再放彩色 🔍 emoji，它与全局单色字形体系冲突」，但搜索中页仍在用。

### P1-7 `⤓` 的无障碍名与实际动作不符

`Md3.kt:198` 的 `GLYPH_NAMES` 把 `⤓` 映射为「下载」，而它在目录页是导出 TXT 的按钮（`showToc()` 里的 `Widgets.button(this, "⤓", "tonal")`）。屏幕阅读器会把导出念成下载。
同一张表还缺 `⟳`、`🔒` 等字形的名字，回退成「按钮」。

### P1-8 同一类副标题四种写法

| 位置 | 写法 |
|---|---|
| 首页最近下载 | `作者 · 已下 X / Y 章` |
| 发现页（番茄） | `作者 · 题材 · 站点` |
| 发现页（起点） | `作者 · 站点`（无题材） |
| 目录页进度卡 | `已下 X · 失败 N` |

分隔符同为中点，字段数却从 2 变到 3，同一列信息没法扫读。

### P1-9 列表内层级未区分

- 书源页第一项「书源市场」有卡片底色，后两项「更新书源库」「下载线程」无底色，三者字号、间距一致。看起来像一处样式丢失。见 `r8-09-sources.png`。
- 作业菜单把书名当标题，却与「重命名」「导出 TXT」「删除」三个动作同一字重，读起来是四个并列动作。见 `r8-06-job-menu.png`。

### P1-10 发现页两组筛选无分组标签

站点（全部/番茄/起点）与频道（男频/女频）两行，样式相同、间距相同、都无标签。观感上是「同时选中两项」。见 `r8-12-discover.png`。

### P1-11 目录行标记宽窄不一

`✓`、`✗`、`🔒` 三个标记的视觉宽度差距大，行尾对齐会跳动。

## 四、文案与密度

### P2-12 开发语汇进界面

搜索结果抬头写「155 条 · 完成 21/30 源 · 9 失败」，书源页写「引擎缺陷 1 条，已自动修补」「不可用 4 条，按原因：」，按钮写「换一批源」，进度写「已下 1645」，市场写「浏览 15」，源名后缀带「（优+）」，兜底书名写「未命名（1234章）·a1b2c3」。这些是内部状态，不是用户语言。

### P2-13 目录页主按钮是死按钮

「已下载」是整屏最大、唯一的填充按钮。点击只弹「本书已下载完成」（`showToc()` 里 `finished -> toast(...)` 分支）。屏幕最显眼的控件没有动作。

**建议**：改成「导出 TXT」或「重新下载」，或降级成状态标签。

### P2-14 副标题截断丢语义

`ellipsize` 在词中间下刀：「从云端拉取最新整包，不必重装 A…」「并发抓正文，太高易…」。省略号后本应有的结论（APK 包、封号）全部丢失。

**建议**：改写短句，不要依赖截断。

### P2-15 字号与点击区低于下限

- `FS_SM = 10 sp`，低于 MD3 最小档 labelSmall 11 sp，也低于手表常用 12 sp。
- `TAP = 34 dp`，用于顶栏图标与阅读器上下章。首页每行 `⋮` 的可点区域约 20 px 见方（10 dp）。

### P2-16 搜索结果同书重复

「2012前传（4 源）」连出 4 张完全相同的卡片。在只有 3.5 行可见的屏上，四倍重复挤掉别的结果。见 `r8-04-results.png`。

### P2-17 搜索阻塞态无出口

卡在「已扫 29 / 30 个源」二十秒，没有进度条、没有取消按钮、没有超时文案。实测 20 秒后自行恢复。

## 五、MD3 合规对照

判据：MD3 的硬性要求分四类——主题与颜色角色、组件与形状、尺寸与触控目标、字号阶与字距。前两类做到大半，后两类整体换成了手表自定档。

### 符合

| 项 | 证据 |
|---|---|
| 颜色角色用 MD3 深色基准值原值 | `primary #D0BCFF`、`onPrimary #381E72`、`surface #141218`、`onSurface #E6E0E9`、`outline #938F99` |
| 靠色调分层，不用阴影 | `surface1..4` = `#1D1B20 / #211F26 / #2B2930 / #36343B`，对应 surface container low→high；全局无 elevation |
| 按钮四族齐全且配色正确 | filled / tonal / outlined / text；tonal 用 `secondaryContainer #4A4458` + `onSecondaryContainer #E8DEF8` |
| 形状 | 按钮圆角 = 高度一半（全圆胶囊）；卡片 `R_CARD = 12 dp` |
| 按压反馈用状态层 | `RippleDrawable` 包 mask |

### 偏离

| 项 | 本项目 | MD3 |
|---|---|---|
| 顶部应用栏 | 36 dp | 64 dp |
| 列表项 | 42 dp | 56 dp |
| 按钮高 | 38 dp | 40 dp |
| 搜索框 | 34 dp | 56 dp |
| 触控目标 | 34 dp | 48 dp |
| 字号阶 | 17 / 14 / 12 / 10 sp | 24 / 16 / 14 / 12 / 11 sp |
| 字距 | 仅 `sectionLabel` 设 `0.05em` | 每档自带字距 |
| 状态层色 | 统一白 8% | 取前景色 8% / 12% |

尺寸压缩在 248 dp 高的屏上是无奈之举，可解释。但 **34 dp 的触控目标没有解释空间**：MD3 与 Wear M3 都要求 48 dp 可点区域，视觉可以小，热区必须够。

`FS_SM = 10 sp` 比 MD3 最小档还小 1 sp，属于直接越界。

### 不符合

| 项 | 说明 |
|---|---|
| 主题 | `Theme.DeviceDefault.NoActionBar`，平台控件走 OEM 主题，这是 P0-4 的总根 |
| 图标 | 用 emoji 与 Unicode 字形，MD3 要求 Material Symbols |
| 对话框 | 缺 28 dp 圆角、surface container high 底色、正确的标题字阶 |
| 无障碍命名 | 字形名与动作错配（P1-7） |

### 结论

「按 MD3 风格做的紧凑变体」成立，「符合 MD3」不成立。要拉回合规，最小四步：
1. `styles.xml` 父主题换 `Theme.Material3.Dark.NoActionBar`。
2. 触控热区补到 48 dp（视觉尺寸不变，用 padding 撑）。
3. `FS_SM` 提到 11 sp。
4. 图标换矢量资源。

前 3 步是小改，第 4 步成本最高。
