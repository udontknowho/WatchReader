## 二、P0 阻塞级

### P0-1 搜索结果标题露出 HTML 标签

- 现象：界面显示 `重生<em>1980</em>`、`重回<em>1980</em>`。
- 影响：搜索结果显示不完整；带高亮标签的书源几乎全军覆没。
- 定位：书源返回 `name` 字段带 `<em>` 高亮，`MultiSource` 聚合后未剥离标签，`showHits` 直接渲染。
- 建议：聚合结果统一做一次标签剥离（去 `<em>`、`</em>` 及其他内联标签），并解码 HTML 实体。

### P0-2 结果行不显示作者与来源站

- 现象：394 条结果只有书名，没有作者，没有来源站名。
- 影响：多源聚合的核心价值丢失。同一本书来自 5 个源时，用户无法区分、无法选择。
- 定位：`MainActivity.kt` 的 `showHits` 拼好了 `sub = 作者 · 源名`，却传给 `Widgets.listItem(twoLine = false)`；`Widgets.kt` 第 127–135 行的非两行分支只放标题与 trailing，**subtitle 被静默丢弃**。
- 建议：改为 `twoLine = true`，或补上单行分支的副标题渲染。

### P0-3 「最近下载」只有标题，下面空白

- 现象：首页有「最近下载」分组标题，下面没有任何条目，也没有空态提示。
- 影响：用户以为功能坏了，且没有任何自救路径。
- 根因：`jobsDir` 是 `files/books`，判定"有书"只看目录是否存在；实际 4 个目录全部 `restore` 失败：

  | 目录 | 性质 |
  |---|---|
  | `7490785501058712088` | 空目录，无 `job.json` |
  | `7515827292661105214` | 空目录，无 `job.json` |
  | `export` | 导出目录，写在 books 里（`MainActivity.kt:764`） |
  | `https:` | 脏 bookId（源 id 未净化） |

- 建议：三步都要做。
  1. 只把含 `job.json` 的目录当作业。
  2. 导出目录移出 `books`（如 `files/export`）。
  3. 判定为空时走空态分支；bookId 落盘前做字符净化。

## 四、P2

- `books` 目录同时承担作业存储与导出落地，结构性问题；即使修了 P0-3，脏目录仍会积累。

## 五、未验证项与原因

目录页、下载、续传、导出 TXT 均未验证，**不是 App 的问题证据**：

1. lamda 虚拟屏的触摸注入活不过约 1 分钟。display state 转 OFF 后，`vd_dump` / `vd_screenshot` 有时仍可用，`vd_click` 全部丢弃（连左上返回键都不响应）。
2. 搜索本身耗时 18 秒，等结果出来时注入通道已失效。
3. 释放并重建虚拟屏无效，重启 lamda 服务才恢复。
4. `termux-clipboard-set/get` 已失效，中文无法注入；本次用 ASCII 关键词「1980」绕过。

真机补测建议顺序：搜索 → 点结果 → 目录 → 下载免费章 → 中断后重进续传 → 导出 TXT → 检查 `job.json` 与 `chapters.jsonl`。

## 六、复现要点

```sh
# 引擎自检
cd ~/WatchReader && bash build.sh test

# 虚拟屏（lamda 需在跑）
cd ~/tmp/lamda
python -c "import mcpc; print(mcpc.call('/vd/mcp/','vd_create',{'name':'t','width':378,'height':496,'densityDpi':320}))"
python -c "import mcpc; print(mcpc.call('/vd/mcp/','vd_start_app',{'name':'t','package_name':'com.watchdl'}))"

# 点击/输入走 root 直注更可靠（displayId 从 dumpsys display 取最大值）
/system/bin/su -c 'unset LD_LIBRARY_PATH LD_PRELOAD; input -d <id> tap 200 105'
/system/bin/su -c 'unset LD_LIBRARY_PATH LD_PRELOAD; input -d <id> text "1980"'
```

截图落在 `/data/usr/uploads/`，权限 `root:root 640`，复制到 `$HOME` 后需 `chmod 644` 才能读。
