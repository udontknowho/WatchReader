## 一、判定

导出功能能跑通，产物也干净，但**用户认不出导出的书**：文件名是一串 URL，首行是「未命名」。

下载列表**没有编辑能力**：长按无菜单，条目无入口，代码里没有删除、没有改名。四条作业里三条叫「未命名」，其中两条连章节数都一样。

两个用例都是「动作存在，产品不成立」。

## 三、用例 A · 下载导出

### A1 两个入口是同一个动作

`⋮`（`MainActivity.kt:277`）与卡片 `⤓`（`:297`）都调 `exportTxt(info)`，传入同一个 `info`，不是菜单。

实测证据：两次导出落在**同一 inode（1641127）**，大小同为 2 593 188 B，mtime 从 `07:26:21` 刷成 `07:26:29`，Toast 文字完全一致。

结论：这不是「双入口」，是同一个按钮摆了两处。用户以为 `⋮` 会开菜单，结果直接开始写文件（第 1 轮 P1-13 的第 2 轮确认）。

### A2 产物质量

| 项 | 值 |
|---|---|
| 文件名 | `https___www.shenhuazhihou.com_book_santi_1018_0726.txt` |
| 大小 | 2 593 188 B |
| 行数 | 12 009 |
| 章头 | 143（另有 1 行首部） |
| 首部 | `未命名` |
| 残留标签 | 0 个 HTML 实体，2 处 `<`（正文自带） |
| 段落缩进 | 11 577 段以全角两空格开头 |

正文清洗合格。首部只有「未命名」一行——作者为空时没有第二行，书名也没落盘。

### A3 边界

| 边界 | 结果 |
|---|---|
| 0 章作业导出 | Toast「还没下到内容，先下载」，`files/export/` 文件数不变。`exportText` 在写盘前就 return，不留空文件。**通过** |
| 下载中导出 | 点导出时目录页显示「已下 26」，快照 28，产物 **27 章**、205 928 B、1 248 行，末章「……微闭上眼睛，沉神感应了一下」完整收尾。半截行被 `readChapters` 丢弃。**通过** |
| 同分钟连点两次 | 仍只有一份文件，`RandomAccessFile` 截断重写。**通过** |
| 并发写 | `exportTxt` 每次起一个新线程，无锁、无去重。实测这一次产物大小正确，但两个线程同时 `setLength(0)` 写同一路径的行为未经保护。**风险，未复现损坏** |

### A4 不可用的地方

1. **文件名是 URL。** `safe` 兜底链是「书名 → `safeDirName(bookId).take(40)` → 未命名」。书名全空，落到第二级，用户看到 `https___www.shenhuazhihou.com_book_santi_`。40 字截断对同站长 ID 还有撞名可能。
2. **Toast 截不住重点。** `已导出 143 章 → https___www.sh…`，用户读完得不到任何信息。
3. **首部书名是兜底值。** 导出文件第一行「未命名」，作者位空着。

### A5 书名为空的两个来源（定位到行）

```kotlin
// MainActivity.kt:818-821  搜索结果点进已有作业时
val job = Downloader.restore(jobsStore(), hit.bookId)
if (job != null) {
    showToc(BookInfo(hit.bookId, job.name, job.author, job.chapters), src)
    return
}
```

```kotlin
// MainActivity.kt:906  首页点进已有作业时
if (job != null) { showToc(BookInfo(bookId, job.name, job.author, job.chapters)); return }
```

两处都**丢掉调用方手里的书名**：`openHit` 手上的 `hit.name` 就是「斗破苍穹」，却拿空的 `job.name` 去建 `BookInfo`。所以目录页标题空白、副标题前导「·」、导出文件名回落 URL。

最小修法（两行）：

```kotlin
showToc(BookInfo(hit.bookId, job.name.ifBlank { hit.name }, job.author.ifBlank { hit.author }, job.chapters), src)
showToc(BookInfo(bookId, job.name.ifBlank { name }, job.author.ifBlank { author }, job.chapters))
```

| 删除 | 无 | 唯一删除是 `cleanDirtyJobs()`（`:1068`），只删没有 `job.json` 的空目录，用户看不见 |
| 改名 | 无 | 无任何写回 `name` 的入口 |

### B2 「未命名」兜底生效，但列表更糟

`displayName = job.name.ifBlank { "未命名" }`（`:197`）已生效，截图 `r2-01` 可见「未命名」。问题是四条作业三条同名为「未命名」：

| 目录 | 书名 | 章节 |
|---|---|---|
| `..._book_doupocangqiong_` | 空 | 48 / 1645 |
| `..._book_qidian...1209977_` | 空 | 0 / 0 |
| `..._book_141035`（若初） | 空 | 0 / 0 |
| `..._book_santi_` | 空 | 143 / 143 |

中间两条**整行完全相同**：`未命名` / `· 已下 0 / 0 章`。用户无法区分，也无法删掉。

副标题还有一个老问题：作者为空时模板照拼分隔点，显示成「· 已下 143 / 143 章」，前导点裸露（第 1 轮 P0-2 的残留）。

### B3 建议（未实现，只给方案）

1. 列表项加 trailing `⋮`：`Widgets.listItem(..., trailing = "⋮")` 目前只有显示、没有点击，需要补一个 `onTrailingClick` 参数（`Widgets.kt:88`）。
2. 点击 `⋮` 弹三选一菜单：**重命名 / 删除 / 导出**。
   - 重命名：写 `job.json` 的 `name` 与 `author`，顺手接住 `openHit` 的空书名，同时修好 P0-2 与导出文件名。
   - 删除：`dir.deleteRecursively()`，必须二次确认，删的是用户下载的全部正文。
   - 导出：复用 `exportTxt`，入口合理，不必再挤在目录页顶栏。
3. 兜底文案改成可区分：`未命名（1645 章）`，或直接显示 `bookId` 的站点名 + 章节数。

## 五、本轮新增问题

### P0-6 · 列表没有任何编辑入口

- 现象：长按无菜单，条目无图标，首页顶栏只有齿轮。用户下完一本书后无法改名、无法删除。
- 影响：失败作业（0 / 0 章）永久占据列表，且与正常作业同名，无法清理。
- 证据：`r2-11`、`r2-01`；代码 `Widgets.kt:88-112` 只绑点击。
- 修法：见 B3。

### P0-7 · 已有作业的书名被丢弃

- 现象：搜索页明明有书名「斗破苍穹」，点进已有作业后目录页标题空白，导出文件名回落成 URL。
- 定位：`MainActivity.kt:820`、`:906`，用空 `job.name` 覆盖了调用方手里的真实书名。
- 修法：两处 `ifBlank { hit.name }`。

### P0-8 · 下载中离开下载页就无法取消

- 现象：下载中点返回或「回到目录」，再想停下时，目录页按钮是「继续下载」，点了只弹「已有下载在跑」（`r2-15`）。带「取消」的下载页再也进不去。
- 影响：我实测的一本 1 645 章的书只能靠 `am force-stop` 才停下。普通用户没有这个手段，只能等它跑完。
- 定位：`startDownload` 的 `if (downloading) { toast("已有下载在跑"); return }`（`:955`）挡住了回程，而 `showProgress` 只在进度广播且当前屏是 Progress 时才被调用。
- 修法：`downloading` 为真时改为**跳转** `showProgress(info)`，而不是弹提示；或把「取消」做成常驻通知动作。

### P1-18 · 导出文件名是 URL，提示被截断

`https___www.shenhuazhihou.com_book_doupo_1018_0734.txt`；Toast 显示 `已导出 27 章 → https___www.sh…`。证据 `r2-04`、`r2-09`。

### P1-19 · 空作者留下前导分隔点

首页副标题「· 已下 0 / 0 章」，目录页副标题「· 1645 章 · 免费 1645」。作者为空时不该拼这个点。

### P1-20 · 杀进程后状态停在 RUNNING

强制停止时实际已下 48 章（`chapters.jsonl` 49 行），`job.json` 仍是 `"state": "RUNNING"`。重新打开会显示「已下 48 / 1645」并可以「继续下载」，但状态是假的。

### P1-21 · 计数比文件慢

下载中导出时：目录页「已下 26」、导出产物 27 章、随后快照 28。三个数字互不同步（第 1 轮 P1-5 再证）。

## 八、复现要点

```sh
# 虚拟屏（378×496@320，手表尺寸）
~/vd/vd.sh start 378 496 320
ID=$(cat ~/tmp/vd.id)
/system/bin/su -c "unset LD_LIBRARY_PATH LD_PRELOAD; /system/bin/am start --display $ID -n com.watchdl/.MainActivity"

# 长按（保留按住状态截图）
(./vd.sh swipe 120 350 120 350 3000 &) ; sleep 1.3; ./vd.sh shot hold.png

# 导出产物检查（需 root）
python3 ~/tmp/an.py /data/data/com.watchdl/files/export/<文件>.txt

# 关掉正在跑的下载（应用内无出口）
/system/bin/su -c '/system/bin/am force-stop com.watchdl'
```

**本轮踩到的环境坑**：本机息屏时间 30 秒（`settings get system screen_off_timeout` → `30000`）。息屏后虚拟屏整组断电，`am start --display` 仍返回成功，但窗口 `visibleRequested=false`、抓帧全黑；解锁后输入注入也会失效，必须 `vd.sh stop && vd.sh start` 重建。连续操作间隔不要超过 25 秒。
