下面按 OPPO Watch 3 Pro 的 189 × 248 dp 真机比例画了渲染。每张卡前面有勾选框，勾完底栏汇总，点复制就能把选择贴回来。

45%顶栏 + 底栏占屏比
136 dp留给正文的高度
1.9 行发现页一屏能看到的条数
48 dp顶栏（40 行高 + 8 间隔）
64 dp底栏（M3 手机档是 80）

先说结论

问题不在“要不要缩小”，而在两块固定栏吃掉了小半屏。屏高只有 248 dp，顶栏 48 加底栏 64 就是 112 dp。
发现页一行的双行高度是 72 dp，136 dp 的内容区只放得下 1.9 行 —— 这就是“列表太大、手表上表现不好”的直接原因：不是行太高，是行数太少。

项目现在可选下限能省
顶栏48 dp0 dp（滚动时隐藏）48 dp
底栏64 dp4 dp（指示条 + 滑动）60 dp

五 · 改这些要动哪里

方案改动点风险
T2 / T3Md3.TAB_H 加 Widgets.headerRow 的内边距与字号低。一处常量，全屏统一
T4滚动区加 scroll 监听，顶栏做透明度与高度动画中。要处理回顶复原与键盘无关的触摸冲突
B2 / B3Widgets.navBar 的高度与是否画标签低。一处函数
B4 / B5新增横滑手势容器，三栏改成 ViewPager 式切换高。现在三屏各自 root.removeAllViews() 重建，要改成常驻三页
D2 / D3discoverItem 改调用参数，listItem 支持自定义行高低
D4发现页列表换成网格布局中。要处理分页加载与滚动位置
D5目录页分组卡换两列按钮低，只动发现页目录
横滑切栏（B4 / B5）是本页里唯一动到导航结构的一条。现在三栏各是一屏一屏重建的，改成常驻三页要动 MainActivity 的切换逻辑。如果只想先见效，C1 那组三处常量就能把可见行数从 1.9 提到 3.1。
